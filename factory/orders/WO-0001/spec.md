# Sieve (`sieve-widget`)
## Purpose
For anyone in a long session who dreads compaction. While on, Sieve answers the compaction itself: every message's text stands word for word, older tool calls and their results fold into short marked lines, and no summarizer request is made. Between compactions the card shows what a sieve would leave. When a sieve would not free enough, or you asked for a summary on your own terms, it steps aside and the engine's compaction runs unchanged. The tail is whole turns, so a compaction that fires deep inside one long turn has nothing older to fold and steps aside; the working card says so beforehand (`Too much: a summary would run`).
## The sieve (pure function `sieve(messages, tailTurns)`)
- A **digest** is a user message whose text starts with `[sieve-widget]`. A **turn start** is a user message with no `toolResults` and non-blank `text` that is not a digest. `SessionMessage` has no field that tells a typed prompt from a core summary, command output or a task notification, so all of these are turn starts: that only moves where the tail begins, and Sieve never claims a count of what the person typed.
- **Tail**: from the `tailTurns`-th turn start from the end to the end, returned untouched, handles and all. Fewer turn starts than `tailTurns`: the whole list is tail and nothing is folded. A text-only user row (a task notification, a queued prompt) can sit between a call and its result, so while any `tool_use_id` among the tail's `toolResults` has no use in the tail, the cut moves back to the turn start before it, or to the start of the list when there is none: a tail never holds a result without its call.
- **Head** (everything before the tail), in order: a user message without `toolResults` (turn starts, digests, image-only rows with `text` `''`) and an assistant message without `toolUses` are kept as they are, with their `handle`. An assistant message with `toolUses`: non-blank `text` becomes a built `{ role: 'assistant', text, toolUses: [] }` (no `handle`), blank text emits nothing, and its calls join the pending fold. A user message with `toolResults` is dropped; non-blank `text` beside the results becomes a built `{ role: 'user', text, toolUses: [] }`. Before any message is emitted, and at the end of the head, a non-empty pending fold is flushed as one digest: a built user message, no `handle`.
- **Digest text**: `[sieve-widget] 3 tool calls folded here by a widget, results dropped (not written by the user): Read src/sum.js; Bash npm test (failed) x2. Run a call again if you need its result.` (`1 tool call folded here` for one). Each call is `tool` plus the first string among `input.file_path`, `path`, `command`, `pattern`, `url`, `query`, `description`, with every run of whitespace (newlines and tabs included) collapsed to one space, trimmed, then cut to 80 characters; `(failed)` when `isError`; identical entries merge as `xN`; at most 40 entries, then `and N more`.
- The digest is a user message because the folded results were user-role messages: nothing is put in Claude's mouth, and the marker says who wrote it. The head of the output holds no `toolUses` and no `toolResults`; no built message has blank text. The function also answers the counts: `kept` = input messages of either role with non-blank `text` that are not digests (every one's text is in the output unchanged), `calls` = calls folded, `lines` = digests written.
## Deciding (`session.compact` hook)
Pass `e` to `next(e)` untouched, in this order, when: the widget is off; `e.agentId` is set; `e.instructions` is non-blank (outcome `asked`). Otherwise weigh, sieve with `tailTurns` 2, and if that is not enough, with 1.
- **Weigh**: `talkChars` = characters of every `text`; `trafficChars` = characters of `JSON.stringify(use.input)` plus `use.text` over every `toolUses` entry. With `context` from `$.session.usage({ breakdown: 'summary' })` (estimated locally, no request): `total = context.tokens ?? context.breakdown?.totalTokens`. `conv` = the `tokens` of the `context.breakdown.categories` row whose `kind` is `used` and `name` is `Messages` (the label the types file documents; `kind` alone cannot single the row out), capped at `total`; with no such row or no `breakdown`, `conv = total`. `rest = total - conv`: only what is not conversation, which no compaction removes. `scale = conv / (talkChars + trafficChars)`, never capped (0 when there are no characters), so tool output denser than 4 characters a token is weighed as traffic and not as `rest`. `talk = talkChars * scale`, `traffic = trafficChars * scale` (so `talk + traffic = conv <= total`), `left = rest + (talkChars + trafficChars of the sieved list) * scale`. With neither `tokens` nor a `breakdown`: `scale = 1 / 4`, `rest = 0`, `total = (talkChars + trafficChars) / 4`.
- **Enough**: `left <= ENOUGH_OF_WINDOW (0.5) * context.window` and `left <= ENOUGH_OF_TOTAL (0.75) * total` and at least one call folded.
- Enough, trigger `manual`, `auto` or `plugin`: return `{ messages }` (no `tokensBefore`, `tokensAfter` or `usage`: the figures are estimates), outcome `sieved` recorded (`face` `outcome`, `last` set with `before` (`total`), `after` (`left`, an estimate until measured), `isMeasured` `false`, `kept`, `calls`, `lines`: the best-moment card), one toast. It does not call `next`, so hooks below do not see it; no shipped widget hooks `session.compact`.
- Enough, trigger `precompute`: return `{ skip: 'Sieve will handle the compaction.' }`. A `precompute` never records an outcome, changes the card or raises a toast; not enough, failed or with instructions it goes to `next(e)`.
- Not enough, `manual`, `auto` or `plugin`: `await next(e)`, then outcome `short` and one toast.
- Thrown while weighing or sieving: `await next(e)`, then outcome `failed`, no toast.
- An outcome that says the summary ran (`short`, `asked`, `failed`) is recorded only after `next(e)` resolved with `messages`. When `next(e)` answers `{ skip }` nothing is recorded and nothing toasted; a throw from `next(e)` is not caught.
- The widget never starts a compaction: `$.session.compact()` is not called anywhere (the engine refuses it from a `command.run` hook), so the hook has one path for every caller and no sieve-only mode.
## Card
Inner width is the card width less 4. `face` picks the state. Value lines truncate (`wrap="truncate-end"`); the empty sentence wraps. `size(n)` is at most 4 characters and always cuts down, never rounds up, so no figure carries into a fifth character: `n` is floored to a whole number, and a negative or non-finite `n` (`NaN`, `Infinity`) reads `0`; under 1,000 the number; under 10,000 `floor(n / 100) / 10` with one decimal and `k` (`1.0k`, `1.2k`, 9,999 is `9.9k`); under 1,000,000 `floor(n / 1000)` and `k` (`142k`, 999,999 is `999k`); under 10,000,000 `floor(n / 100000) / 10` with one decimal and `M` (`1.2M`, 9,999,999 is `9.9M`); then `floor(n / 1000000)` and `M` (`12M`), capped at `999M` (999,999,999 and anything larger read `999M`). Every token figure and every count on the card, in a toast and in an answer goes through `size()`. `message`, `text`, `call` and `line` follow `plural(n, word)`, which reads the raw count: exactly 1 is singular (`Every word of 1 message kept`, `1 tool call folded to 1 line`, `1 text kept`), anything else plural. Long wording at an inner width of 36 or more (a 40 column card), short wording below; no long line exceeds 36 characters and no short line 16, whatever the values. Title `Sieve`; the note (at most 10 characters) is at the right of the first row.

Long and short wording of the rest (`long` | `short`):
- Working: `about 23k conversation` | `23k talk`; `about 119k tool traffic` | `119k tools`; `A sieve leaves about 31k` | `leaves 31k`.
- Working, `isEnough` false, a dim line: `Too much: a summary would run` | `too much left`. With `last.kind` `sieved`, a dim last line: `Last sieve: about 142k to 31k` | `last 142k → 31k`.
- `short` (note `passed on`): the two lines drawn | `118k: not enough`, `summary ran`.
- `asked` (note `passed on`), the same for every trigger, since `plugin` instructions come from another plugin and not the person: `Compaction came with instructions`, `The usual summary ran with them` | `had instructions`, `summary ran`.
- `failed` (note `failed`): `Could not sieve this conversation`, `The usual summary ran` | `could not sieve`, `summary ran`. `unread`: the two lines drawn | `could not read`, `tries next turn`.
## Commands
- `/sieve-widget`, `on`, `off`: the switch, as the standard has it. Switching on looks at once. Unknown (`now` included): `Usage: /sieve-widget [on|off]`.
- There is no `now` verb: a compaction cannot be started from a `command.run` hook, and a bare `/compact` already sieves while the widget is on. The working card says beforehand whether it will (`A sieve leaves about ...`) or not (`Too much: a summary would run`). There is no `clear`: nothing is collected.
## Data
- `on('session.compact')`: reads `e.trigger`, `e.agentId`, `e.instructions`, `e.messages` (`role`, `text`, `toolUses[].tool`, `.input`, `.text`, `.isError`, `toolResults`, `handle`). Once per compaction. Answers `SessionCompacted` `{ messages }`, `SessionCompactSkipped` `{ skip }`, or `next(e)`. `$.session.usage({ breakdown: 'summary' })` is also read once per compaction.
- **Look** (one function): reads `$.session.messages()` and `$.session.usage({ breakdown: 'summary' })` (`context.tokens`, `context.window`, `context.breakdown.totalTokens`, `context.breakdown.categories[].name`, `.kind`, `.tokens`), weighs and sieves as the hook does. No message holds a `toolUses` entry (or there are no messages): `preview` `null`, `face` `empty`. Otherwise `preview` set, `face` `working`. Either call throws: `preview` `null`, `face` `unread`. It runs when the switch goes on, at `session.start` when the restored switch is on, and on each measure below.
- `on('session.measure')`: when on, `e.changed` includes `context` and `e.context.tokens` is defined: first, if `last.kind` is `sieved` and `last.isMeasured` is `false`, it sets `last.after` to `e.context.tokens` and `isMeasured` to `true` (the first measured size after the sieve replaces the estimate, once; `tokens` is absent from a compaction until the next response, so the best-moment card keeps its estimate until then); then it looks. Otherwise it reads nothing and changes nothing. Once per main-thread turn. Always returns `next(e)`.
- `$.ui.toast(text)`: `Sieve: about 142k to about 31k, every word kept, no summary.` or `Sieve would not free enough (about 118k left): the usual summary ran.`
- `on('session.start')`, `on('command.run', { command: 'sieve-widget' })`, the three `on('ui.render')` hooks, `$.command.register`, `$.widgets.card`: from the template.
## State and storage
- `$.state` `isOn: boolean`, `face: 'empty' | 'working' | 'outcome' | 'unread'`, `empty` at first. A recorded outcome sets `outcome`; a look sets one of the other three.
- `$.state` `preview: { total: number; talk: number; traffic: number; left: number; isEnough: boolean } | null` (tokens, estimated). `null` while off, when the transcript holds no tool call, and when a look failed.
- `$.state` `last: { kind: 'sieved' | 'short' | 'asked' | 'failed'; before: number; after: number; isMeasured: boolean; kept: number; calls: number; lines: number } | null`. `short` holds `before` and `after` (the `left`) and zeros; `asked` and `failed` hold zeros; `isMeasured` is `true` only on a `sieved` whose `after` a measure replaced.
- `$.store` `isOn`. No files, no timers (no `sync`).
## Off
The `session.compact` hook returns `next(e)` at once, `session.measure` does no work, no toast, no card. Switching off sets `preview` and `last` to `null` and `face` to `empty`.
## Demo
The engine lacks `$.session.messages` and a transcript for `engine.compact()`. Stand-ins needed: a transcript of four finished turns (a prompt, six tool calls with results of about 20,000 characters in all, a text answer each) that grows by one such turn per scripted turn; `$.session.messages()` returning it; `engine.compact()` dispatching `session.compact` with those messages, each given a `handle`. The engine's `usage({ breakdown })` already answers a `Messages` row; it must grow with the stand-in transcript. Without these the page shows only `Could not read the conversation`, and the widget must not ship so. At rest: the working state, `about 46k`, conversation small, tool traffic large, `A sieve leaves about ...`. After the scripted turn: the same with larger figures (`about 50k`). After the page's compact button: the best moment.
## Cost
None: no model call, and it removes the summarizer request. Claude loses older tool output and may read a file again. The next request rewrites the prompt cache, as after any compaction.
## Acceptance
How the tests prove these: the test engine's `$` has no `state` noun, so `face`, `preview` and `last` are proven through the card, the toasts and what the hook returns. The kit's bottom `session.compact` hook answers `{}`, which the engine rejects, so every case that reaches `next(e)` lists a stand-in plugin after the widget (beneath it) that answers `{ messages }` or `{ skip }` and reports the `e` it received inside its result; "`next` not called" means that stand-in's mark is absent from the result.
- A1: on with no messages, and on with a transcript of prompts and text replies but no tool call, the card says `Nothing to sieve yet.` and what will appear, with no note; the same whether switched on by the command or restored at `session.start`.
- A2: with a transcript that holds tool calls, switching on, a restored switch at `session.start`, and a measured turn each give the note `about <total>` and a body of conversation, tool traffic and `A sieve leaves about <left>`, with `talk + traffic <= total`; a preview that is not enough adds `Too much: a summary would run`; the next measured turn after a sieve returns the working state with `Last sieve: about <before> to <after>`, where `<after>` is that turn's measured `tokens` and not the estimate (an estimate of 31k and a measure of 28,000 read `to 28k`, under a note of `about 28k`), and a second measured turn at 35,000 leaves it `to 28k`; when `$.session.usage` reports neither `tokens` nor a `breakdown`, switching on and a compaction take their figures from text length alone and still read `about`.
- A3: an `auto` compaction of a realistic transcript (text-only replies, mixed text and tool replies, tool-only replies, parallel calls, a failed call) returns `{ messages }` in which every turn start and every text-only assistant message is the input object with its `handle`; no message before the tail has `toolUses` or `toolResults`, no built message has blank text or a `handle`, and every `tool_use_id` among the tail's results has its use in the tail; `First, ok, Second, [call], a text-only task notification, [result], fin, Third, ok` at `tailTurns` 2 keeps the call and its result together in the tail (the cut is at `Second`), with nothing folded from that turn.
- A4: a head assistant message with text and tool uses comes back as a built assistant message with the same text and no tool uses; a tool-only one is gone; a user message with tool results and text keeps its text as a built user message; a user message with blank text and no tool results keeps its `handle`; a core summary row, a command-output row and a task-notification row (user, text, no tool results) each come back as the input object with its `handle` and count in `<n> messages`, and no card line, toast or answer contains `your messages`.
- A5: each run of folded calls becomes exactly one user message starting `[sieve-widget]` that names every tool with its file or command, marks failures `(failed)`, merges repeats as `xN`, and says it was not written by the user; a 500-character command is cut to 80 characters, a heredoc command with newlines and tabs gives an entry on one line with single spaces, and 60 distinct calls list 40 and `and 20 more`; sieving a list that already holds digests keeps them unchanged with their handles, does not count them in `kept`, and does not treat them as the start of a turn.
- A6: the last two turns keep every message, handle, tool use and tool result; when that is not enough but one turn is, only the last turn is kept whole; a transcript with fewer turn starts than `tailTurns` comes back from `sieve` as the same objects in the same order with nothing folded, and a compaction of it goes to `next(e)`.
- A7: after an `auto` sieve the card shows `sieved`, `About <before> to about <after>`, `Every word of <n> messages kept`, `<calls> tool calls folded to <lines> lines` and `No summary written, no tokens spent`, and one toast was raised; a bare `/compact` (trigger `manual`, no `instructions`, and with blank `instructions`) sieves exactly the same, `next` not called; a sieve that keeps one message (the head opens on an image-only prompt and every reply before the tail is tool-only, enough at `tailTurns` 1) and folds one call into one line reads `Every word of 1 message kept`, `1 tool call folded to 1 line`, at 20 columns `1 text kept`, and its digest starts `[sieve-widget] 1 tool call folded here`; two of each read `messages`, `texts`, `calls`, `lines`.
- A8: when the sieved size is over half the window, or over three quarters of the total, or nothing was folded, the hook returns what `next(e)` returned with `e` unchanged, the card shows the note `passed on`, `A sieve would leave about <left>` and `Not enough: the usual summary ran`, and one toast says the usual summary ran.
- A9: non-blank `instructions` reach `next(e)` unchanged with the same messages; under trigger `manual` and under trigger `plugin` alike the card shows the note `passed on`, `Compaction came with instructions` and `The usual summary ran with them` (short: `had instructions`, `summary ran`), no card line says `You` or `/compact`, and no toast is raised; with `agentId` set the hook returns `next(e)` unchanged and state does not change.
- A10: `precompute` answers `{ skip }` when a sieve would be enough and passes to `next(e)` when not, when sieving throws and when instructions are given, and none changes the card or raises a toast; with the widget off a compaction returns exactly what `next(e)` returns and nothing is written, toasted or stored; when `next(e)` answers `{ skip }` for a not-enough, an `asked` or a failed compaction, the hook returns that skip, the card does not change and no toast is raised.
- A11: `/sieve-widget now` and any other unknown verb answer `Usage: /sieve-widget [on|off]` and leave the card as it was; no verb of the widget dispatches a `session.compact` (the stand-in beneath the widget sees none, and no toast is raised), and the widget's source holds no call to `$.session.compact`.
- A12: a throw inside the hook's sieving under `auto` (a tool input holding a BigInt, which passes the engine's validation of messages and makes the weighing throw) ends in `next(e)` and the card `failed`, `Could not sieve this conversation`, `The usual summary ran`; when `$.session.messages()` rejects as the switch goes on, the card shows `no reading`, `Could not read the conversation` and `The next turn tries again`, with no toast and no text about a summary, and a later measured turn that reads returns the working state; a `session.measure` whose `changed` lacks `context`, and one whose `context.tokens` is undefined, call neither `$.session.messages` nor `$.session.usage` and leave the card as it was, so after a sieve the outcome keeps showing; switching off after a sieve and on again looks afresh: the working card, with no `Last sieve` line.
- A13: with a total of 1,234,567 tokens, 1,234 messages kept, 1,212 calls folded and 120 lines: every state (empty, working with both dim lines, sieved, short, asked, failed, unread) at 20 and at 39 columns uses the short wording with no line over the inner width, and at 40 and 60 columns the long wording with no line over 36 characters; no token figure is cut. `size` reads 999 as `999`, 1,000 as `1.0k`, 1,212 as `1.2k`, 9,999 as `9.9k`, 142,000 as `142k`, 999,999 as `999k`, 1,234,567 as `1.2M`, 9,999,999 as `9.9M`, 12,345,678 as `12M`, 999,999,999 as `999M` and 5,000,000,000 as `999M`, never more than 4 characters, and `NaN`, `Infinity` and -5 as `0`; with totals of 9,999, 999,999 and 9,999,999 the working card's note is at most 10 characters and no line passes 16 or 36.
- A14: with `tokens` 100,000, a `Messages` row of 80,000 and a transcript of 8,000 characters of text and 152,000 characters of tool traffic, all the traffic before the tail (2 characters a token), the working card reads `about 4.0k conversation`, `about 76k tool traffic` and `A sieve leaves about 24k`, with no `Too much` line, and an `auto` compaction sieves with `About 100k to about 24k`; the same transcript with no `Messages` row weighs the whole 100,000 as conversation (`about 95k tool traffic`, and a sieve leaves between `5.0k` and `5.9k`); a `Messages` row larger than `tokens` is capped at `tokens`; with `tokens` absent and a breakdown `totalTokens` of 100,000 the figures are the same as the first case; the hook and the look call `$.session.usage` with `breakdown` `summary`.
