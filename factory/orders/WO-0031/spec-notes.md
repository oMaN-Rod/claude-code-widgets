# Spec notes: WO-0031 Attic

The spec passes. Every call it names is in the types file (`plugin-authoring/types/claude-code.d.ts`, 2.1.289): `tool.describe` with `ToolDescribeInput` (`tool`, `description`, `isDeferred?: true`, `provider: Origin` with `plugin`), `ToolDescribeResult`, `ToolDeferral`; `ToolCallInput` with `AgentLoop.agentId`; `TurnCompleteInput`; `$.session.usage({ breakdown: 'summary' })` with `context.breakdown.categories` of `ContextCategory` (`tokens`, `kind` `deferred`); `$.tool.list()` with `ToolInfo.name`; `$.session.repo()` (`SessionRepo.root`), `$.session.root()`; `$.ui.invalidate` with `'tool.describe'` in `InvalidatableEventName`. The drawings fit (36 inner at 40 columns, 16 at 20). 108 lines, 15 acceptance lines, `shows` 185 characters. Settle these while building; each will be looked at on the bench.

1. Dry run with a personal move. After `stow` or `keep` in the dry run the card still reads `Nothing moved yet.` and `show` still opens `watching, nothing moved.` above a row `away <tool>: stowed by you`. On the card, treat the dry run as the spec treats airing: when the person's lists move something, the counts row follows the dry-run rows (or takes the place of `Nothing moved yet.`), so the card never denies a move the person just made. Keep the `show` first line as the Live section writes it; the rows carry the move. Add this case to the A9 test.
2. Describes that arrive before the plan is ready. They pass through and are not recorded, and with an empty plan there is no invalidate to raise them again. If that happens in a real session the dry run counts too few tools (`<k> never called`) and `since` starts late. Record the tool on a pass-through describe too (the record needs only `e` and `n`, not the plan), or show in the live run that describes come after `session.start` has finished. A1 and A12 should cover the order.
3. Narrow fetch row for a tool stowed by the person. The 20-column drawing gives `fetched PowerSh…` only. Say what stands in for `Stowed by you, so it stays.` under 30 columns (for example a second row `stays stowed`), and test it in A14.
4. `fetched <tool> and <k> more` at 20 columns: the cut must keep `…` and the row inside 16 characters whatever the name; decide whether `and <k> more` survives narrow or becomes `+<k>`.
5. Plurals. `1 tool in the attic, 1 forward.`, `1 tool never called here so far.`, `Attic cleared: 1 tool forgotten`: all through `plural()`. Zero cases: a plan with only forwards reads `0 tools in the attic, 2 forward.` and note `0 away`; decide whether that is the wanted wording (for example note `2 forward`) and draw it in a test.
6. `kilo` rounding. Say which way 999, 1049, 1050, 99 950 and 100 000 go, and make the difference row the difference of the two unrounded sums, not of the two rounded figures (3.1k and 8.4k must not give 5.2k). A negative or zero sum never prints a sign twice.
7. Baseline against a changed session. `base` comes from the latest session with an empty plan; an MCP server added or removed since then shifts the on-demand sum for a reason that is not Attic's. The card will then credit or blame the attic for it. At the least, do not print a difference row larger than the on-demand figure itself; say in the test for A5 what is shown.
8. Switching off mid-session resets `book` while it may be dirty (calls counted since the last `turn.complete`). Either write the book once before the reset when the session is counted, or state in a test that those calls are dropped. Off must still write nothing afterwards.
9. `show` with many tools. A session with several MCP servers can give dozens of rows. Set a cap (for example 20 rows, then `and <k> more`) so the answer stays readable.
10. The floor is seven tools. Evidence may stow built-ins the engine's own instructions lean on (`Skill`, `Agent`, `AskUserQuestion`, `TodoWrite`, plan-mode tools). They stay one ToolSearch step away, so this is within the spec, but the live run should show Claude still reaching a stowed tool when asked; if it does not, log it and send the order back to design.
11. Tool names in answers. An MCP name can be 60 characters; `show` rows and the verb answers print it whole (one line each), the card cuts it. A name typed with surrounding spaces or in another case resolves to the tool's own spelling (A9).
12. Demo seed. The four engine tools need `seen` 11 and `isDeferred` false, and `WebFetch` `isDeferred` true, or the at-rest card will not read `4 away`, `1 forward`. With `sessions` 11 the session is number 12, outside airing; keep it so.
