# Done (`done-widget`)
## Purpose
For anyone who has heard "done" from Claude while the tests were still red. The person writes what finished means for this task, one line per item, once. Claude is told the list with the next prompt and has a tool, `tick`, to mark an item met with the evidence that proves it. The card shows which items are met and on what evidence. When a main-loop turn ends with an answer that claims the work is done while items are open, the widget counts it and puts a dim suggestion in the prompt box naming the open items.
## What is dropped from the earlier version, and what each fault becomes
- Dropped: the second command `/done-when` (it also switched the widget on, which a verb may not do; it is now the verb `add`); Claude adding items of its own and the `by` field (the list is the person's); several ticks in one call (one item per call); wrapped rows (rows truncate, `show` prints them in full); 10 items of 160 characters (now 6 items of 80, evidence of 120); the tool name `done` (now `tick`, which says what it does).
- The earlier version also worked while off: `clear`, `drop`, the tool, the prompt block and the compaction hook never read the switch. Now every hook but `session.start`, `command.run` and `ui.render` returns `next(e)` first when off, and every verb but the switch answers `Done is off.`
- Fault "one long test that never checks the off state, restore from the store, the placements or a narrow card": one test per acceptance line; A12 and A13 are the off state, A1 the restore, A15 the placements and the narrow card.
## The tool (`tick`), and why there is one
The idea is Claude marking an item itself, with evidence; no hook can infer that. `$.tool.register` has no opposite, so after a switch-off the tool stays listed until the session ends; its hook then answers an error and changes nothing.
- Registered by `$.tool.register({ name: 'tick', description, inputSchema })` at `session.start` when the switch is restored on, and at every switch-on (registering again replaces it). The model calls it as `mcp__done-widget__tick`.
- description: `Tick one item on the user's definition of done, with evidence. The user keeps a checklist of what finished means for this task; you are told it with a prompt. When you have met an item and verified it, call this with its number and what proves it: the command you ran and its result, or the file and line. Tick only what you have verified. Do not tell the user the work is finished while items are open: say which are open and why.`
- inputSchema: `item` (number, required: `The number of the item on the checklist.`), `evidence` (string, required: `What proves it: the command you ran and its result, or the file and line.`).
- Served by `on('tool.call', { tool: 'mcp__done-widget__tick' })`, from any loop. Every answer is `{ result: said, text: said }`, with `isError: true` where marked. In this order:
  1. Off: error `Done is off; nothing was ticked.`
  2. No items: error `The definition of done is empty; there is nothing to tick.`
  3. `e.item` not a `number` that is whole and from 1 to the count: error `There is no item <String(e.item), cut to 20 characters>. The list:` and the list.
  4. `e.evidence` cleaned (`String(e.evidence ?? '')`, each run of whitespace one space, trimmed, cut to 120). Empty: error `Item <n> needs evidence: the command you ran and its result, or the file and line.`
  5. Otherwise the item's `evidence` is set (a second tick of the same item overwrites it) and the answer is the list, a line break, then `Still open: 2, 3.` or `Every item is met.`
- The list, here and everywhere: one line per item, `<n>. [ ] <text>` when open, `<n>. [x] <text> (<evidence>)` when met, numbered from 1.
## Telling Claude, and pulling it up
- `on('prompt.submit')`: off, or `e.origin.kind` not `composer`, `bridge` or `sdk`, or `isDue` false, or no items: `return next(e)`. Otherwise `isDue` becomes false and the hook returns `next({ ...e, context: [...(e.context ?? []), block] })`.
- block: `done-widget: the user's definition of done for this task. Tick each item with the tick tool as you meet it, giving the evidence that proves it, and do not call the work finished while any is open:` then a line break and the list.
- `isDue` becomes true on `add`, on `drop`, on a switch-on, and at `on('session.compact')` when on, `e.agentId === undefined`, `e.trigger !== 'precompute'` and the result of `next(e)` has no `skip`. That hook returns what `next(e)` resolved to, unchanged.
- `on('turn.complete')`: `const ended = await next(e)`, returned unchanged in every case. A nudge happens when on, `e.agentId === undefined`, `e.isAborted` is false, `e.reason === 'answer'`, at least one item is open, and `e.answer` claims the work is done by the claim rule below. A nudge adds 1 to `nudges` and calls `$.prompt.suggest({ text })`, whose rejection is caught and ignored. text: `Item 2 on the done list is still open. Meet it and tick it with evidence, or say why not.`; with several, `Items 2, 3 on the done list are still open. Meet them and tick them with evidence, or say why not.`
- The claim rule, in one pure function `claims(answer, items)`. An answer claims when at least one of its clauses claims (step 4) and is not quiet (step 5). A bare claim word in the middle of a clause is never a claim. No model call; an answer of 400,000 characters is judged in well under 100 ms.
  1. Prepare: lower-case the answer. Take out every item's own text, and the phrases `done list`, `definition of done` and `done-widget`. Replace each numbered reference (`item 2`, `items 2, 3 and #4`, joined by `,`, `&`, `and`, `or`) with the one word `item`. Replace `everything but` and `all but` with `except`.
  2. Sentences: split after each `.`, `!`, `?` and line break. A sentence that ends in `?` is dropped. In a sentence where a colon is followed, before the sentence ends, by a count of failures (a whole number other than 0, then a word starting `fail` or the word `error` or `errors`: `2 fail`, `3 failures`, `1 error`), the clause that ends at that colon is dropped.
  3. Clauses: split each sentence at `.` `,` `;` `:` `!` `?`, a line break, a dash with a space on both sides, and the words `but`, `and`, `though`, `although`, `however`, `while` and `so` (not `so far`).
  4. A clause claims when, trailing punctuation and symbols aside, it ends in a claim word (`done`, `finished`, `complete`, `completed`, `fixed`, `resolved`, `all set`) or in a whole-work phrase, either one followed by any number of closers. A whole-work phrase is `finished`, `completed`, `done with` or `finished with`; then optionally `implementing`, `building` or `writing`; then `everything`, `it all`, `all of it`, `all the work`, `all of the work`, or `the`/`this`/`that`, optionally `whole`/`entire`, and one of `work`, `task`, `job`, `refactor`, `refactoring`, `implementation`, `migration`, `rewrite`, `change`, `changes`, `fix`, `feature`, `update`. The closers are `now`, `here`, `too`, `already`, `as well`, `for you`, `as requested`, `as asked`, `as planned`, `successfully`, `correctly`, `properly`, `fully`, `entirely`.
  5. A clause is quiet when any of these holds. Hedge: it holds `not`, `never`, `no`, `nothing`, `none`, `nor`, `cannot`, `without`, `except`, `far from`, `nowhere near`, `yet to`, `so far`, `almost`, `nearly`, `mostly`, `mainly`, `largely`, `partly`, `partially`, `half`, `still`, `remaining`, `remain`, `remains`, `open`, `once`, `until`, `when`, `if`, `before`, `after`, `will`, `to be`, `need`, `needs`, `needed`, or a word ending `n't`. Item: it holds `item` or `items`, unless as `all`/`every`/`each`, optionally `of`, optionally `the`, optionally a number (digits, or `two` to `six`), then `item(s)`. Run: its claim is `done`, `finished`, `complete` or `completed` (closers allowed) and directly before that word stands a process that ran: one of `test(s)`, `test run(s)`, `suite(s)`, `build(s)`, `run(s)`, `command(s)`, `install(s)`, `download(s)`, `compile(s)`, `script(s)`, itself followed by any number of `is`, `are`, `was`, `were`, `has`, `have`, `had`, `been`, `just`, `now`, `also`, `all`, or by `'s`; or the closing backtick of a code span; or a command name, one of `bun`, `npm`, `npx`, `pnpm`, `yarn`, `node`, `deno`, `tsc`, `eslint`, `prettier`, `vitest`, `jest`, `pytest`, `cargo`, `go`, `make`, `git`, `docker`, `pip`. `fixed`, `resolved` and `all set` after a process still claim (`The build is fixed.`).
  6. Meant, and not to be patched away: a partial claim nudges even beside an admission (`The retry is done. Items 2 and 3 are open.`, `The first step is done.`, a status line `- retry: done`), and so does `Well done!`; a claim word that does not end its clause is quiet (`Fixed it.`, `I have fixed the bug.`, `Done (see the diff).`, `The build finished with 3 errors.`).
## Card
Inner width is the card width less 4. Long wording at an inner width of 36 or more, short below. Title `Done`. Note: none when empty, `all met` when every item is met, else `<met>/<count> met`. An item is one row, `<mark> <n> <text>`: the mark is a green `✓` when met, a yellow `·` when open. A met item has a second, dim row: four spaces and its evidence. Item and evidence rows are one line each (`wrap="truncate-end"`). The nudge line is yellow, last, and present only when `nudges > 0`: long `Said done too soon: <plural(nudges, 'nudge')>`, short `<plural(nudges, 'nudge')>`. The empty card's sentences are dim and wrap at any width.

## Commands
One command; `argumentHint` and usage `[on|off|add <criterion>|drop <number>|show|clear]`. The verb is the first word, in any case; the rest keeps its case.
- bare, `on`, `off`: the switch. On: `Done on; /done-widget add <criterion> writes the list. /widgets places it.` Off: `Done off. The tick tool stays listed until the session ends and ticks nothing.` Unknown input: `Usage: /done-widget [on|off|add <criterion>|drop <number>|show|clear]`, nothing changed.
- `add <criterion>`: the text is cleaned (each run of whitespace one space, trimmed, cut to 80) and appended as an open item. Answers `Item <n>: done when <text>. Claude is told with your next prompt.` No text: `Add what? Try /done-widget add the tests pass`. Text already an item: `Already on the list as item <n>.` Six items: `The list is full (6 items). /done-widget drop <number> makes room.` The last three change nothing. Off: `Done is off.`
- `drop <number>`: removes that item, later items move up one. Answers `Dropped item 2: <text>`. `<number>` missing, not digits, or no such item: `There is no item "<what was typed, cut to 20>". /done-widget show lists them.`, nothing changed. Off: `Done is off.`
- `show`: what Claude is told. `<plural(count, 'item')>, <met> met:`, the list with every text and evidence in full, and when `nudges > 0` a last line `Said done too soon: <plural(nudges, 'nudge')>`. No items: `The definition of done is empty. /done-widget add <criterion> adds an item.` Off: `Done is off.`
- `clear`: items become empty, `nudges` 0, `isDue` false. Answers `Done list cleared.` Off: `Done is off.`
## Data
- `on('session.start')`: nothing of `e`. Once per load.
- `on('command.run', { command: 'done-widget' })`: `e.args`.
- `on('tool.call', { tool: 'mcp__done-widget__tick' })`: `e.item`, `e.evidence`. Once per call Claude makes.
- `on('prompt.submit')`: `e.origin.kind`, `e.context`. Once per prompt; attaches at most one block, only when due.
- `on('turn.complete')`: `e.answer`, `e.agentId`, `e.isAborted`, `e.reason`. Once per turn.
- `on('session.compact')`: `e.agentId`, `e.trigger`, `skip` of the result. Once per compaction.
- `$.tool.register`, `$.prompt.suggest`, `$.store.get`, `$.store.set`, `$.command.register`, `$.widgets.card`, the three `on('ui.render')` hooks, `fit()`, `plural()`.
- No `$.clock`, no `$.fs`, no `$.session.cwd`, no timer (no `sync`), no model call.
## State and storage
- `$.state` `isOn: boolean`.
- `$.state` `list: { items: { text: string; evidence: string }[]; isDue: boolean; nudges: number }`. Blank: no items, `isDue` false, `nudges` 0. `evidence` `''` is an open item. At most 6 items; text at most 80 characters, evidence at most 120.
- `$.store` `isOn: boolean`, the only key. The list is for one task and lives in this session only.
- No files.
## Off
No card. `session.start` registers the command and reads `isOn`; no tool is registered. The `prompt.submit`, `turn.complete` and `session.compact` hooks return `next(e)` and touch nothing: no block, no nudge, no suggestion. The tool, if an earlier switch-on registered it, answers its error and ticks nothing. `add`, `drop`, `show` and `clear` answer `Done is off.` Switching off writes only `isOn`; the list stays in `$.state`, so a switch-on in the same session shows it again and tells Claude again.
## Demo
The list is the person's and the engine's scripted turn calls no plugin tool, so both need stand-ins. When the card is switched on, the page runs `/done-widget add the tests pass` and `/done-widget add the fix is committed`. Two scripted calls dispatched through `tool.call` like the others: after the last `npm test`, `{ tool: 'mcp__done-widget__tick', input: { item: 1, evidence: 'npm test: passed' } }`; after the `git commit`, `{ tool: 'mcp__done-widget__tick', input: { item: 2, evidence: 'commit 3f2a1c9 on main' } }`. At rest: note `0/2 met` and two `·` rows. After the scripted turn: note `all met`, two `✓` rows each with its evidence row, no nudge line (the engine's answer claims nothing while items are open).

## Cost
No model call. The tool's description and schema ride in every request while it is listed, about 130 tokens. The list is attached to one prompt after each change to it, each switch-on and each compaction: at most 6 items, about 350 tokens.
