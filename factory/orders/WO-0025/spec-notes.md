# WO-0025 Customs: spec notes (second review, after the send-back from inspection)

The spec passes. The three faults of the send-back are fixed in Terms: a comment cut at an unquoted `#`, a redirection rule (with a lone `&` ending the segment), a much longer value-flag list, and a Python word of digits and dots ignored. A2 and A3 carry the cases; the count is still 15 acceptance lines in 107 lines. Nothing else in the spec changed, so the card, the gate, the verbs and the hooks stand as built. The rebuild is confined to the word parser and the A2/A3 tests. The notes of the first review that the build already settled are not repeated.

1. **Order of the word rules.** Do them in this order per word, on the raw word before quotes are removed: lone `&` ends the segment; unquoted `<`/`>` cut (and the next-word drop); then the `-` and value-flag rules; then the name rules. A quoted word skips the redirection rule entirely (`'requests>=2'`, `"lodash@>=4"`).
2. **A redirection glued to a name.** `npm i lodash>out.log` leaves `lodash` and `pip install requests>=2` leaves `requests` with `asked` empty (the shell really does write a file named `=2`). `>>out.log`, `>> out.log`, `2>/dev/null`, `<in.txt` and `1>&2` leave nothing. Put one or two of these beside the A2 cases.
3. **A heredoc or here-string** (`<<EOF`, `<<< "x"`) is cut like any `<`; the body lines after it are separate segments and will not start with an install form, so nothing is read from them. Do not add a rule; make sure it does not throw.
4. **PowerShell's `2>$null`** makes the segment hold `$`, so the whole segment is not read and the install goes through unchecked. That is the spec as written (it errs toward silence); do not special-case it, but log it if the live run meets it.
5. **`--flag=value`** starts with `-` and is dropped whole; it must not also drop the next word, even when the flag is in the value list (`--python-version=3.12 requests` keeps `requests`).
6. **Value flags that are booleans in one tool.** `-w` (pnpm workspace root), `-f` (npm force), `--color`, `--optional` and `--workspace` take no value in some tools, so `pnpm add -w lodash` drops `lodash` and nothing is looked up. That is a miss, never a false hold, and is acceptable; keep one list for all tools as the spec says.
7. **The comment cut comes before the split,** line by line, so `npm install lodash@4 # add lodash; npm i evil` reads one segment. `#` inside a word (`user/repo#branch`, `pkg#1`) is not a comment. A `#` inside quotes is not a comment.
8. **Digits and dots, Python only.** `pip install 3.12` is ignored; an npm word of digits (`npm i 2`) is still a name by the npm pattern. Leave it so.
9. **The ninth name of one command** (finding 4 of the inspection): Terms and A9 still say it is `unchecked` and not fetched. The build took only eight and listed nothing for the ninth. Since the list holds eight, either is invisible on the card; make A9 prove whichever the build does, with no fetch for the ninth.
10. **Demo** (finding 5 of the inspection): `docs/engine.js` still needs the scripted install and the URL-answering `http.fetch` of the Demo section, or the card never leaves its empty state on the demo page and under `render.ts --turns`.
11. **`widget.json` cost** still omits `api.npmjs.org`, which the Cost section names. Add it if it fits.
