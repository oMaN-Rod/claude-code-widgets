# WO-0012 Ledger: spec notes

No blocking fault. The machinist settles these while building; each is looked at again at inspection.

1. **Row `mine` at 40 columns has no room for a two-digit dollar figure.** Inner width is 36. `this session $12.40` (19) and `since 23 Sep 2025` (17) make 36 with no gap, so any session between $10.00 and $99.99 on a two-digit day runs the two parts together or cuts one. Keep at least one space between them: when both do not fit, the right part gives way (drop `since `, then the whole date), never the money. Add the case to the A15 test (`this session $12.40`, `since 23 Sep 2025`, 40 columns).
2. **Only unpriced entries.** A scan that finds `isOurs` files with no cost record, before any turn is measured, leaves the empty state with nothing counted: total `$0.00`, `0 sessions`, and a `since` with no date to show. Draw no `since` when nothing is counted, and make sure no `Invalid Date`, `NaN` or `Infinity` can reach the card or the `show`/`scan` summary.
3. **Switching on by command.** The spec names `open($)` for it but the read of `ledger.json` only at `session.start`. Read the file on switch-on as well, or the card says `Nothing counted yet.` over a project that already has a record until the first turn ends.
4. **A file too long to read is not "without a cost record".** A session over 3,500,000 bytes very likely has one; these are also the dearest sessions. Either word the row and the summary so it is true of both kinds (for example `<n> not priced` / short `<n> unpriced`), or keep the two apart. The limit itself stands.
5. **Money rounding at the boundary.** 99.995 to 99.999 must not print `$100.00`; decide on the rounded value (`$100`). Negative, `NaN` and non-finite `usd` from `session.usage` are already excluded: keep that true of anything read back from `ledger.json` too (a hand-edited or half-written file must not break the card).
6. **`ledger.json` shape.** "Missing or unparseable reads as `{ projects: {} }`" should also cover a file that parses to the wrong shape (`null`, an array, `projects` not an object, an entry missing `usd`).
7. **Two sessions writing at once.** Read, change one entry, write is not atomic; a turn end in one session can drop the entry another wrote in the same instant. The spec accepts this silently. Keep the window as small as possible (read immediately before the write, nothing awaited between but the write) and since `usd` is a running total, the next turn end restores it.
8. **`name` when `roots[0]` ends in a separator or is a drive root** (`C:\`, `/`): the last segment is empty. Fall back to the path itself so the note and the answers are never blank.
9. **Candidate folders and `enc`.** `enc(r)` must be taken from the path as git prints it and as `$.session.root()` gives it; on Windows git prints `C:/Users/...` and Claude Code encodes `C:\Users\...`. Both give `c--users-...`, so this works, but prove it in A5 or A4 with a Windows root rather than only `/work/project`.
10. **`scan` answer with nothing to read.** `Read 0 saved sessions of <name>.` is fine; check the plural, and that a second scan straight after a first (everything skipped) reads as intended rather than as a failure.
11. **Call names are unproven against the types.** No generated types file is on this machine. `size` on `fs.list` entries, `cost?.usd` on `session.usage()`, `isStdoutTruncated`, `$.plugin.root` and `$.env.get` are all in shipped widgets, so they pass here; the live run is what proves the saved-session shapes (`"type":"cost-state"`, `totalCostUSD`, a first `cwd` line, that a running session's file can be read while it is written).
12. **Subagent costs.** The spec asserts a subagent's cost is inside its session's record; the earlier version read `subagents/*.jsonl` separately. If the live run or a real saved session shows otherwise, say so in the build log rather than adding a silent second source.
