# WO-0034 Earshot: spec notes (second spec, after the director's send-back)

The spec passes. The three faults of the send-back are addressed: the Live recipe waits with `bun -e "await Bun.sleep(30000)"`; an `sdk` or `bridge` prompt is heard at its own event and untimed, so the run can no longer answer `not heard` or a false span; a waiting message no longer depends on an attachment, the next main-loop `turn.step` of its turn hears it. Checked in the types file (2.1.289): "A prompt typed while a turn ran fires at Enter", `turnId` "typed over that turn, or delivered into it", `TurnStepChunk`, `messageCount` on the step input, `TurnCompleteReason` with four reasons, `queued_command`, `backgroundedToDeliverMessage`, `TimerCall`, `InvalidatableEventName`. The new 40-column rows fit 36 and the new 20-column rows fit 16. 120 lines, 15 acceptance lines. Settle these while building; each will be looked at on the bench.

1. **Four narrow sentences do not fit 16 characters.** At 20 columns `Turn ended first.` is 17, `Nothing ran first.` 18, `Went to background` 18 and `Own turn, 48s later.` 20, and the spec says rows are cut, not wrapped. A cut status sentence is a fault at inspection. Use forms that fit, for example `Turn ended.`, `Nothing ran.`, `Backgrounded`, `Own turn +48s` (check with a 3-character and a 6-character span), and test each at 20.
2. **The `turn.step` hook form.** I confirmed the event's types exist but not the exact shape of a streaming hook. Take `async function*` and `return yield* next(e)` from the types' own example, pass every chunk and the result untouched, and mark the message heard before the first `yield`, not after the stream ends.
3. **Heard by a step is an inference.** No live run can show the `composer` path. Keep the claim narrow in every string: "heard" is the start of the next request of that turn. A message recorded while a step is already streaming must not be heard by that step (it is recorded after the hook began, so this holds if the mark happens only at the hook's start; test it).
4. **Do not double-hear.** When both an attachment and a step arrive, the first sets `settledAt` and the second changes nothing. A7 covers the attachment asked twice; add the step after the attachment and the attachment after the step.
5. **Untimed message and the turn events.** A `heard` untimed message is never turned to `missed` or `own`, takes no calls into its list, starts no timer and gets no `isPushed`. As an earlier row it reads `"<text>" · heard`.
6. **The slash guard.** "The guard the build already has" is not a rule. Write it down in the test name: a text whose first character is `/` leaves no message, whether or not `next` rewrote it.
7. **A message with no text matches everything.** An empty stored text "appears in" any attachment and any `turn.start` text. An empty-text message is heard by the step only (never by attachment text) and is never turned to `own` by text.
8. **Cut text and matching.** Match on the stored 80 characters without the `…`, which is drawn only. A message of whitespace only is `(no text)` too.
9. **`last` with changes and no reads.** Write `Changes first: <labels>.` and never `; 0 reads.`
10. **Earlier rows at 20 columns.** Cut the text, not the word: `"a long mess…" · 3s late`.
11. **States described but not drawn.** `own turn`, the background row, reads only and `+<n> more` at 40 columns have no drawing; build them from the Rules paragraph and show each at 20 and 40 in the tests.
12. **Waiting with calls counted.** No `Before it heard you:` heading until the message is heard; while waiting the `!` rows and the reads row follow the `behind` row directly, as drawn.
13. **`turn.complete` then `turn.start`.** A main-loop end followed at once by the start of the same text ends as `own`, with the same span, measured from Enter, on the card and in `last`.
14. **`flight`.** Drop an entry by `tool_use_id`; with several in flight the `behind` row moves to the next oldest.
15. **Labels.** A multi-line command collapses to one row; a `file_path` with back slashes gives its file name only; the 60-character cut comes before the card's own cut, so at most one `…`.
16. **Live run.** If the build writes attachment types to a file for the director's `--keep` run, the spec does not name that file: do not write one unless the director asks, and remove it before inspection.
