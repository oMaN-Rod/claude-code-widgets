# Spec notes, WO-0028 Amendments

No blocking fault. Every hook and call named was found in the types file (2.1.289): `prompt.compose`, `tool.describe`, `turn.complete`, `next.trace` / `TraceEntry.plugin` / `.returned`, `Origin`, `$.session.version()`, the traits and the section ids. Settle these while building; each is looked at again at inspection.

1. Version line at 20 columns. The drawing cuts the running version (`2.1.287 → 2.1.2…`), the one fact on that row the person cannot guess. Under 30 keep the new version whole and cut the old one, or drop the spaces round the arrow (`2.1.287→2.1.289` is 15). State the cut rule for the row in general: a development build's version (`2.1.280-dev.20260920.t101500.sha1a2b3c4`) overflows at 40 and 60 too, in this row, in `2.1.289 is new here (was …)`, `Baseline taken at …` and `No change since …`. Those are sentences that wrap, so check they wrap without breaking the border on an unbroken 40-character token.
2. `loose` across a version change. The flush does not say what happens to `loose` when `before` becomes the old `now`; A9 implies it is kept. Keep it, and say so in a test. An id that has left both shots can be dropped from `loose`.
3. The age. `age` is taken when the report is built, so `2.1.289 here for 9d 4h` stands still through a long session. Acceptable (no timer), but rebuild the report at each flush even when the file did not change, as the flush already says, and do not let A6 pass only on a frozen clock.
4. Two sessions, one file. The flush is read, change, write with no lock. Two sessions ending a turn together can lose one side's added tool. Read immediately before the write and keep the window to that one tick; a lost tool must cost a later comparison and never produce a false row or a fault.
5. `clear` in mid-session. `held` is reset, so the next main render captures the sections again, but tools already described this session are not described again: the new baseline may read `14 sections, 0 tools`. Write `plural(0, 'tool')` correctly and make sure A13's "next turn takes a baseline" holds with no tool. This also makes the "at most one state write per session" in Data "one per capture".
6. Demo seed. "Two other lines in `tone`" must come out as exactly `+4 -2` and `t/Bash` as `+0 -3` for the best-moment card "exactly as drawn": the seeded `tone` holds two lines where the new one holds four, the rest equal. The seed's `last` must be `claude-demo||`.
7. The key when the first main render is not the book of `last`. The working card says "(was 2.1.287)" from the `last` book; if the session's key turns out to be another book, the turn ends on a baseline card instead of a comparison. That is right, but test it (A10 covers the book, not the card after a `new` look).
8. `show` with a `before` and loose entries only: the line reads `No change since <before> (<key>).` followed by the `Left out` line. Check the two read well together, and that a key with empty parts (`claude-x||`) is not ugly in that header; trailing `|` may be trimmed for display only.
9. `show <n>` numbering must be the card's numbering even when the file changed under another session between the card and the verb: the verb reads the file, the card reads `report`. If they differ, the verb's own header (label and fact) makes that visible; do not index `report.rows` with a number computed from the file.
10. A diff of an empty text. `''.split('\n')` is one empty line: a `new` section of three lines must read three `+ ` lines, not four, and `+a -b` must never count a phantom line. Same care for a trailing newline on one side only.
11. Diff output cut at 200 lines: say whether the 200 counts context and `…` lines (it should count printed lines), and keep `<k>` the number of printed lines left out.
12. The malformed-answer path in A3 ("a hook body that throws still returns that answer"): also cover an engine trace entry whose `returned` is undefined (outcome `rejected` or `skipped`), which must fall back to what `next` resolved and never save `undefined` texts.
13. Wording: Terms says "Nothing else is done in either hook" while Data gives `tool.describe` "Never `$.ui.invalidate`"; `tool.describe` is in `InvalidatableEventName`, so keep that rule in the code as a comment-free fact: no invalidate anywhere in the module.
