# Strays (`strays-widget`)
## Purpose
For anyone who has met `port 3000 is already in use` an hour after Claude started a dev server for one check and never stopped it. The card lists the processes this session started that still hold a TCP port, with port, name, age and turn, and one verb stops one. The next session in the same project opens with the survivors already on the card. No model, no tokens. Kept from the idea: rows tied to the session, survival across sessions, `stop`, `forget`, `clear`, Docker shown but never killed. Settled: ports only (a watcher with no port is not shown); a listener the widget cannot tie to this session is never shown, so nothing on the card is a guess; verbs name the port, not a row number, because numbers shift when a row goes and a stop cannot be undone.
## Terms
- Windows: the session cwd matches `/^[a-z]:[\\/]|^\\\\/i`. Otherwise POSIX. `$.process.run` has `timeoutMs: 15000` for a listing and a kill and `timeoutMs: 45000` for a facts call (measured on Windows at full load: 11.4 to 12.4 s, 7.5 s of it PowerShell starting; no process call is on Claude's path and a `$` wait costs a hook no budget).
- Listing. Windows: `['netstat', '-ano', '-p', 'TCP']`; a listener is a `TCP` line whose remote column is `0.0.0.0:0` or `[::]:0` (the state word is localised and not read); port is the digits after the last `:` of the local column, pid the last column. POSIX: `['lsof', '-nP', '-iTCP', '-sTCP:LISTEN', '-Fpn']`; `p<pid>` sets the pid for the `n<addr>:<port>` lines after it. A pair is `<port>/<pid>`, each once.
- Facts: `{ pid, parent, born, name, command }` per process, `born` in epoch ms, and `host`, the pid that runs the widget's own children. POSIX: `['sh', '-c', 'echo "self $PPID"; exec ps -axo pid=,ppid=,lstart=,args=']` with `env: { LC_ALL: 'C' }`; `host` is the `self` number, `born` the five `lstart` words parsed as a local date, `name` the base name of the first word of `args`. Windows: `['powershell', '-NoProfile', '-NonInteractive', '-Command', <script>]`, where the script prints `self<TAB>$PID`, then for `$PID`, each asked pid (digits only) and their parents up to 8 levels one line `pid<TAB>parent<TAB>born<TAB>name<TAB>command line`, read with `Get-CimInstance Win32_Process -Filter "ProcessId=<n>"` per process (measured here under load: the whole table 37 s, one filtered query 3 s, `netstat` 2 to 4 s); `host` is the first process above `self` that is not `cmd`, `powershell` or `pwsh` (the live chain was self, `cmd.exe`, `claude.exe`); `name` drops `.exe`; white space in the command line is one space.
- Window: `{ from, to, turn, isDocker }` for one Bash or PowerShell tool call; `to` is 0 while the call runs and counts as now. A time is inside a window when `from - 2000 <= time <= to + 2000`. `isDocker`: the command matches `/\b(docker|podman)\b/`.
- Chain: from the listener up through `parent` while the parent is in the facts, was born no later than its child, has a pid over 4 and is not `host`; at most 8 steps. The top is the last process reached.
- Ours: some chain member was born inside a window, and either the top's parent is `host` or the top itself was born inside a window (a detached process whose shell has gone). `host` itself is never ours. The row's `turn` is that window's turn. So a server the person started in another terminal (its chain ends at their own old shell) and an MCP server (no member born inside a window) are not ours.
- Shared: the name is one of `com.docker.backend`, `wslrelay`, `wslhost`, `vpnkit`, `docker-proxy`, `rootlessport`, or the pid is 4 or less. A shared listener is a row only when a window with `isDocker` ended at most 60 s before it was first seen; its name is shown as `docker`.
- Label: `name`, or `name (hint)` when the name is one of `node bun deno python python3 py ruby java dotnet php`: the hint is the first word of the command after the executable that does not start with `-`, quotes stripped, base name without extension, cut to 12 characters.
- Asking and running. A hook asks for a refresh by setting `isQueued` true and returns; it never starts one and never waits for one. While on, one timer, `$.clock.every(1000, tick)`, started and cancelled in `sync`, runs them: a tick with `isQueued` true and `isBusy` false sets `isBusy` true and `isQueued` false, runs one refresh and sets `isBusy` false in a `finally`; any other tick reads state and does nothing. So refreshes run one at a time, any number of requests during one start exactly one more, and no code awaits a promise another dispatch made. `stop` is the only other caller (see Commands).
- Refresh: (1) listing; a failure sets `fault` and changes nothing else; a success empties `fault`. (2) With `seen` null the store key is read (the one read per `open`) and its rows are checked as `open` says; then the pairs become `seen` and the refresh ends: what listened before the widget looked is never examined. (3) Rows whose pair has left the listing are dropped. (4) Pairs not in `seen`: one facts call for their pids; each ours or shared-and-allowed becomes a row, up to 9 rows; all join `seen`. A facts failure sets `fault` and leaves those pairs out of `seen` for the next refresh. (5) `at` is now; if the rows changed the store key is written. A refresh that ends after the switch went off writes nothing.
## Card
Title `Strays`. Note: none with no rows; `<n> from earlier` (tight `<n> earlier`) when n rows are earlier; else `<n> running`. Inner width is the card width less 4. A row at 30 or more: left `:<port> <label>` cut with `…`, right `<age>  <mark>`, the age `span(at - born)`, the mark `turn <n>`, `earlier` or `shared` (shared wins). Under 30 (tight): the left part alone. At most 5 rows, then `+<n> more`. Sentences are wrapped by words.

## Commands
`/strays-widget [on|off|stop <port>|forget <port>|clear]`. The verb is matched without regard to case. Bare, `on`, `off` and the usage as in the template. `<port>` is digits, 1 to 65535, with an optional leading `:`; anything else answers the usage. No second command, no tool.
- `stop <port>` waits only on its own `$` calls, never on a refresh it did not start. A row on that port is taken as it stands on the card, with no refresh first, whatever is in flight. With no row, in this order: a pair in `seen` on that port (examined and not ours, or just stopped) answers at once `Nothing of this session's is on port 3000.`; `isBusy` or `isQueued` true answers at once `Still checking ports; try stop 3000 again in a moment.`; otherwise `stop` sets `isBusy`, runs one refresh itself, clears `isBusy` in a `finally`, and then takes the row, or answers `Could not check port 3000: cannot list ports: netstat failed.` (or `...: cannot read processes.`) when `fault` is set, or the `Nothing` sentence. With the row. Shared: `Port 5432 is held by Docker's shared process (com.docker.backend); stop the container instead.` Otherwise one facts call for the pid: absent, or `born` differs, drops the row and answers `Port 3000: that process has already gone.` Else `['taskkill', '/PID', '<pid>', '/T', '/F']` on Windows, `['kill', '<pid>']` on POSIX. Exit 0: every row of that pid goes, the store key is written, `Stopped node (vite) on :3000 (pid 1234).` Otherwise the row stays: `Could not stop pid 1234: <first line of stderr, or "exit <code>">`. A pid equal to `host` is never killed.
- `forget <port>`: drops the row and answers `Forgot :3000 (node, pid 1234); it is left running.` Its pair stays in `seen`, so it does not come back. None: the `stop` sentence.
- `clear`: empties the rows and deletes the store key: `Cleared 2 strays from the card; nothing was stopped.`
- While off, `stop`, `forget` and `clear` answer `Strays is off.` and run nothing.
## Data
Verified in this build's types (`plugin-authoring/types/claude-code.d.ts`, 2.1.289; `plugins/*/.claude-plugin/types/` is absent from this checkout).
- `on('session.start')` (`e.cwd`): the template's work, then `sync`; if on, `open`: set `isBusy` false (a reload may have cut a refresh short) and `isQueued` true, and run no process. The first refresh, in the timer, reads the store key and, with stored rows, makes one facts call: a stored row still in the listing with the same `born` is kept, `isEarlier` true when the stored `session` is not `$.session.id()`; the rest are dropped and the key rewritten. If `rows` is already non-empty (a reload) nothing is restored. Switching on runs `open` and `sync` too.
- `on('turn.start')` (`TurnStartInput`, main loop only by the types): if on, `turn` goes up by one.
- `on('tool.call', { tool: 'Bash' })` and `on('tool.call', { tool: 'PowerShell' })` (`e.command`; any loop): if on, append a window with `to: 0` (newest 50 kept), `const result = await next(e)` with `e` untouched, set `to` and `isQueued` true, return `result` itself. A `next` that rejects closes the window and rejects. No hook on Claude's path ever starts or awaits a process.
- `on('turn.complete')`: if on and `e.agentId === undefined`, set `isQueued` true; `return next(e)`.
- `$.clock.every(ms: number, fn: () => void): Timer` (`TimerCall`; `cancel()` stops it; "timers run until cancelled or until the module reloads"): the one timer above, the reference's named way for work that outlives a dispatch. `fn` is `() => { void tick($).catch(() => undefined) }`. `HookBudget.ms` is 10 000 of a hook's own time and only its own `next` and `$` calls stop the clock, which is why nothing here awaits a foreign promise. Whether a refresh begun in a timer callback runs to its end is what the Live run proves.
- `$.process.run(argv, init): Promise<ProcessRunResult>` (`exitCode`, `stdout`, `stderr`; rejects when the command cannot start or times out): per refresh one listing and, only with new pairs, one facts call. `$.clock.now()`, `$.session.id()`, `$.session.root()`, `$.store.get/set/delete`, `on('command.run', { command: 'strays-widget' })`, the three `on('ui.render')` hooks, `$.widgets.card`. Drawing reads state only.
## State and storage
- `$.state` `isOn: boolean`.
- `$.state` `watch: { turn: number; host: number; at: number; fault: string; isBusy: boolean; isQueued: boolean; seen: string[] | null; calls: StraysWindow[]; rows: StraysRow[] }`, blank `{ turn: 0, host: 0, at: 0, fault: '', isBusy: false, isQueued: false, seen: null, calls: [], rows: [] }`.
- `StraysRow`: `{ port: number; pid: number; born: number; name: string; hint: string; turn: number; isEarlier: boolean; isShared: boolean }`. `StraysWindow`: `{ from: number; to: number; turn: number; isDocker: boolean }`.
- `$.store` `isOn`, and `rows:<hash(folder(root))>`: `{ session: string; rows: StraysRow[] }`, read once per `open`. No command text is stored. No file.
- Module level: the timer handle, `let timer: Timer | undefined`, and nothing else that changes. No map of promises: `isBusy` and `isQueued` say all there is to know about a refresh. Two sessions open in one project each write what they see and the later write wins; a row lost that way is missing from the next session's card and is never stopped.
## Off
No card, no timer (`sync` cancels it), no process call, no window recorded, no store write but `isOn`. `tool.call`, `turn.start` and `turn.complete` pass straight to `next(e)`. Switching off sets `watch` back to blank; the store key is kept so the next `open` can check it. Nothing is ever stopped by switching off.
## Demo
`docs/engine.js` answers every non-git `process.run` with exit 0 and no output, and its root is POSIX (`/demo/...`). Stand-ins needed for this widget: a store value under the demo root's key holding one row from another session (`:3000`, `node`, hint `vite`, born two hours ago); `lsof` answering that listener, and after the scripted turn's first Bash call a second one on `:5173`; the `sh -c ... ps` call answering `self`, both processes and their parents, the second born at that call. At rest: the best-moment card, `1 from earlier`. Both frames are drawn after the engine's clock has run one tick past the request. After the scripted turn: two rows, the new one marked `turn 1`, note `1 from earlier`. Without the stand-ins the card must draw the empty sentence, not throw.
## Live
`bun factory/tools/live.ts factory/floor/plugins/strays-widget --allow "Bash" --say "/strays-widget on" --say 'Use Bash with run_in_background true to run exactly this, then answer ok: bun -e "Bun.serve({port:47613,fetch:()=>new Response(String(1))})"' --say "Use Bash to run exactly this, then answer ok: sleep 15" --say "Use Bash to run exactly this, then answer ok: sleep 15" --say "/strays-widget stop 47613" --say "/strays-widget stop 47613" --say "/strays-widget off"`
Three small turns; the two waits give the listing and the facts call over 30 s to end before the first stop, so the first answer says whether a row was made. A good run answers the first stop `Stopped bun on :47613 (pid <n>).`, the second `Nothing of this session's is on port 47613.`, and the store prints `isOn` false and a `rows:` key with no row. The first stop read otherwise: `Nothing ... on port 47613.` means a refresh ran to its end and the tie failed (log what the facts call printed: the chain and `host`); `Still checking ports` means no refresh ended in 30 s, so the timer's work does not finish or the facts call is far slower than measured; `Could not check port` names the call that failed; `no command.run hook answered` means the hook still overruns its budget. The stop itself may take 15 s on a loaded machine (its own facts call), within the 20 quiet seconds of `live.ts`; read by the sentences, not by position. Afterwards list the ports once and kill anything left on 47613 by hand. The earlier-session card needs a second session and a detached server; ask the owner first, in the scratch project.
## Cost
None: no tokens, no model call, nothing added to a prompt. While on, one port listing after each Bash or PowerShell call and each turn end, off Claude's path, one process query only when a new listener appears, and a one-second timer whose idle tick reads state and runs nothing.
## Acceptance
Tests give `process.run`, `session.id`, `session.root`, `session.cwd` and the clock through `ground()`'s `answers`, record every argv, use real `netstat`, `lsof -F`, `ps` and script output as fixtures, and move the clock to fire ticks; "after a tick" below means that.
- A1: on with no rows the card shows the empty sentence and no note; listeners in the first listing never become rows and cause no facts call; restored off, `session.start` runs no process and starts no timer.
- A2: after a Bash call and a tick, a new `3000/<pid>` whose chain is node, a shell, then `host`, with node born inside the call's window, becomes the row `:3000 node (vite)`, `turn 1`, note `1 running`; the listing and facts argv are exactly those of Terms for a Windows cwd and for a POSIX cwd, the facts call with `timeoutMs` 45000 and the listing with 15000; a row whose pair has left the listing is gone after the tick that follows the next main-loop `turn.complete`.
- A3: a new listener whose top has no parent in the facts and was born inside a window is a row; so is one born after the window whose parent was born inside it; a PowerShell call and a subagent's Bash call open windows too; a call still running counts as a window; a subagent's `turn.complete` asks for no refresh; `turn` counts `turn.start` events while on.
- A4: no row, and no second facts call for the pair, when the top was born outside every window with a parent that is not `host`, when the chain reaches `host` with no member born inside a window, when the listener is `host`, and when the only in-window process is above a parent born later than its child.
- A5: with no tick fired, `session.start`, a Bash `tool.call` and `turn.complete` run no process and leave `isQueued` true; the `tool.call` resolves to the very object `next` gave, with its input unchanged, and a `next` that rejects rejects; while on exactly one `$.clock.every(1000, ...)` is live however often `on` is said, and off cancels it; a tick with nothing asked runs no process; with a listing that never answers, three calls and five ticks start no second listing, and once it answers the next tick starts exactly one more.
- A6: while a refresh is in flight whose listing never answers, `stop 3000` resolves each time: for a row on the card it runs the `born` check and the kill and answers `Stopped ...`, with no listing of its own; with no row and a `seen` pair on 3000 it answers `Nothing of this session's is on port 3000.` and with none `Still checking ports; try stop 3000 again in a moment.`, both with no process run; the second answer is given too when a refresh is only asked. With no row, no such pair and nothing asked or in flight, `stop` runs exactly one listing itself, a tick during it starts no other, and `isBusy` is false afterwards even when the listing rejects.
- A7: a stored row from another session id, still listening with the same `born`, is on the card after `session.start` and one tick, marked `earlier` with note `1 from earlier`; one with another `born` or no longer listening is dropped and the key rewritten; a row stored under this session id is not marked; `C:\Work\P` and `c:/work/p/` read the same key.
- A8: `stop 3000` and `stop :3000` check `born`, then run `taskkill /PID <pid> /T /F` on Windows and `kill <pid>` on POSIX, answer `Stopped node (vite) on :3000 (pid 1234).`, remove every row of that pid and write the key.
- A9: `stop` runs no kill and answers its sentence when no row is on the port, when the pid is absent or `born` differs (row dropped), and for a shared row; a kill that exits 1 answers `Could not stop pid 1234: ...` and the row stays.
- A10: a new listener named `com.docker.backend.exe` first seen within 60 s of a window whose command held `docker` is the row `:5432 docker` marked `shared`; without such a window, or after 61 s, it is no row.
- A11: `forget 3000` answers its sentence, the row does not return at the next refresh while the pair listens, and no kill is run; `clear` answers the count, empties the card and deletes the key.
- A12: a listing that exits non-zero or rejects shows the red row `Cannot list ports: netstat failed.` (`lsof` on POSIX) above the rows still held, and the next good listing removes it; a facts call that fails shows `Cannot read processes.` and the same pair is examined at the next refresh.
- A13: the `netstat` fixture with IPv4 and IPv6 lines of one port, a localised state word, UDP and connected lines yields each pair once; the `lsof -F` fixture likewise; `node C:\p\node_modules\vite\bin\vite.js`, `python -m http.server 8000`, `"C:\Program Files\nodejs\node.exe" server.js` and `postgres -D data` label as `node (vite)`, `python (http.server)`, `node (server)` and `postgres`.
- A14: at 20, 40 and 60 columns no row of any state is longer than the inner width, tight rows are drawn at 20 and wide at 40, a long label is cut with `…`, six rows draw five and `+1 more`, a tenth stray is not added, and the working card is the same in all three placements.
- A15: while off the three verbs answer `Strays is off.`, a Bash `tool.call` reaches `next` and records nothing, and no process runs; switching off blanks `watch` and a refresh that ends afterwards writes nothing; `what`, `stop`, `stop abc` and `stop 70000` answer the usage naming all five verbs; the store never holds a key but `isOn` and `rows:<hash>`, and no file is written.
