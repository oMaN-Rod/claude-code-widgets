# Spec notes: WO-0024 Outage

The spec passes. Every call it names is in the types file (`plugin-authoring/types/claude-code.d.ts`, build 2.1.289): `tool.call` with `ToolCallResult`'s three forms (`deny`, answered, `isError: true` with `text`), `$.http.fetch` with `HttpInit` and `HttpResponse`, `$.clock.sleep` with `SleepOptions.signal`, `$.clock.every` (`TimerCall`), `$.process.run` with `timeoutMs` and `exitCode`, `$.ui.toast`. The `{ deny: text + note }` form for an errored result is what `redact-widget` ships. The drawings fit (16 inner at 20 columns, 36 at 40). 114 lines, 15 acceptance lines. Settle these while building; each will be looked at on the bench.

1. Program words are too wide for a test run. `npm test`, `bun test` or `yarn jest` failing with `Test timeout of 5000ms exceeded` is a network failure naming npm by the Terms as written, so a failing test fetches npm's status, and on a day npm has an incident the sentence lands on a test failure. A6 even expects `npm test && git push` to check npm. Narrow it: a program word names its provider only with an install-like word after it (`install`, `i`, `ci`, `add`, `update`, `publish`, `dlx`, `view`, `npx`/`bunx` themselves, and the like for pip, cargo, uv, poetry), or drop `timeout`/`timed out` for a provider named by program word alone. Say which you chose in the build log, and keep A6's chain case honest (GitHub alone, unless the text names npm's host).
2. Stranger at 20 columns: `no page: gitlab.com` is 19 characters in 16, so the host, the only news in the row, is cut. Truncate from the label, not the host (for example `gitlab.com: none`), and cut a long host in the middle or at the left.
3. `Could not check crates.io's status` is 34 characters: at 30 to 33 inner columns the wide form is cut. Use the short name there or switch to the short form when the wide one does not fit, for every row, not only at the 30 mark.
4. The poll toasts `GitHub reports the incident resolved.` on `elsewhere` too, while the card then says `GitHub: other incident (...)`. Keep the toast true: it is the related incident that cleared; make sure the two do not read as a contradiction (A9 tests only `clear`).
5. A remote such as `https://user:token@host/path` must yield `host` alone: no user, token or port on the card, in `check`'s answer or in state. Add a case to A7.
6. Age: "drawing reads state only", so the age is `checkedAt - startedAt` and stands still between polls. The sentence's `open <span>` must use the same figure as the card. A `started_at` that does not parse, or is in the future, must not give `NaN` or a negative span: fall through to the time of the check.
7. A reused fresh report (A8) for a verdict `incident` shows the age as of the last check, up to 3 minutes stale; fine, but the sentence must not be added twice in one call when two providers both report (join once, one `deny`).
8. `check` while an `incident` report turns `clear`: no toast, by the spec; the poll must then stop (`sync` after the change) and must not toast a minute later for the same change.
9. `unread` on a re-check of a key that held `incident`: the Terms say the poll leaves the report as it was, but a failure-time check "replaces the report of its key". Do not lose `toldId` or wipe an open incident with `unread` from a failure-time check; keep the incident and say so only if you can draw it cleanly.
10. Stacking: if a hook above or below has already turned the errored result into `{ deny }` (`redact-widget` does), this widget sees no `isError` and stays silent. That is what A15 asks; note it in the report so the director knows the two do not compose.
11. The veto's bare `401`, `403`, `404` as whole numbers can match a port, a byte count or a line number in an otherwise real outage text. Accept it (the veto errs toward silence) but test one such text so the behaviour is chosen, not accidental.
12. The 2 s sleep that loses the race still runs to its end; in `command.run` and the poll there is no `next.signal` of a tool call, so make sure nothing is written by a late branch after `clear` or `off` (A14 covers off; cover `clear` the same way).
13. Demo: the stand-ins named (a failing `git push` and a `githubstatus.com` answer in `docs/engine.js`) are the shipper's to add; the build must still rest without throwing on today's `text: 'ok'` answer, which is an `unread` if it is ever reached.
