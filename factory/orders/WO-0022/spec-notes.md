# Spec notes: WO-0022 Aim (first spec review)

The spec passes. Every hook and call it names is in the types file (`plugin-authoring/types/claude-code.d.ts`, 2.1.289): `on('tool.check', { tool })` with `ToolCheckInput` (`tool`, `input`, `tool_use_id?`) and `ToolCheckResult` (`decision`, `reason?`, `rule?`, `hook?`), `$.process.run` with `cwd` and `timeoutMs`, `$.env.get` by string literal, `$.fs.read`, `$.fs.exists`, `$.session.cwd`, `$.clock.every` (`TimerCall`), `$.clock.now`, `HookBudget.ms` 10 000 with waits on `$` not counted. The quotations are as the file has them. All nine risks of the idea are settled. Six states are drawn; the frames fit 36 and 16 except note 1. 120 lines, 15 acceptance lines: at the limit, so a later edit must cut before it adds. Settle these while building; each will be looked at on the bench.

1. **Empty drawing, third row.** `kube context, cloud profile, project,` is 37 characters in a 36 inner width. The card wraps by words, so the built frame will break one word earlier; do not force the drawing.
2. **Quoted text is split like code.** Segments split at `;`, `|`, `(` inside quotes too, and a tool name anywhere outside the head gives a yellow `not known: not a direct call`. So `git commit -m "fix kubectl wrapper"`, `grep kubectl README.md` and `psql -c "select 1; select 2"` each put a line in the dialog. The second is asked for by A9; keep it. But a dialog that cries `not known` for a commit message teaches people to ignore the line. Where it is cheap, do not split inside one pair of quotes, and at inspection the live frames will be read for this noise.
3. **"Whole word" needs one meaning.** Take it as a space-separated word after the head rule (folder part and `.exe` dropped), not a `\b` match: `ls ~/.aws`, `cat aws/config`, `cd terraform` and `--name=helm-chart` must give no line. Test two of these in A9.
4. **`cd` and `terraform` on Windows.** A `cd` to an absolute path (`C:\infra`, `/c/infra`, `/mnt/c/...`) replaces the folder, not joins it; a Git Bash `/c/...` path given to `$.fs.read` may not resolve. When the joined path cannot be trusted, say `terraform workspace not known`, not `default`.
5. **`tf` ambient `default` from the lock file alone.** `.terraform.lock.hcl` with no `.terraform/environment` is `default` only for local state; that is the tool's own rule, so it stands, but a `terraform` segment in a folder with neither file should be not known (`no workspace found here`), never `default`.
6. **`aws` with nothing at all.** No key, no profile, no config file, and an asked `aws s3 ls`: the Terms give no ambient target, so the line is `aws profile not known: ...` and needs a why of its own (`no profile found`); `aws did not answer` would be untrue, no probe ran.
7. **`psql` and `PGHOST` in the overlay.** `PGHOST=h psql` and `export PGDATABASE=app` should be read through the overlay like the rest, and the source is then `named in the command`. `-h` given with ambient `PGDATABASE` and no `-d`: show the host alone or with the database, but pick one and test it.
8. **The key row.** `key …` plus four characters, cut with `…` at 20 columns, reads `aws key …AB12`; make sure the row's own `…` and the cut's do not sit side by side. The last four of an access key id are not secret; the secret key is never read. Keep it so.
9. **`changed` after `clear` and after off.** `clear` zeroes every `since`; switching off blanks the rows, so the first refresh after `on` is "first seen" again and carries no `changed`. A11 should cover the second case.
10. **Production match on a not-known aim.** `kubectl --context "$PROD_CTX" delete ...` is not known and so never `PRODUCTION`. Correct by the spec; do not match the words against the raw command.
11. **`show` punctuation.** `Production words: prod, live.` ends in a full stop after a word; fine. `Last:` then the line: put them on two lines, as the Live section expects.
12. **Reason joined with core's.** ` · ` then core's reason can make a long dialog line. Aim's line goes first, as specified; do not cut core's reason.
13. **For the director: the dialog itself is unseen by any run.** The headless Live run proves the hook saw an ask and wrote the reason. That a person reads it in the dialog, and that it sits beside the Stakes line with both widgets on, needs one interactive look before shipping, as the spec asks. Record it in the log.
14. **Live run on this machine.** The session may reach for the PowerShell tool in place of Bash; both are hooked, so `Last:` should still appear. If the verdict is not `ask` (a rule allows or denies it outright), there will be no `Last:`; that is the spec's stated behaviour, and the log should then carry the verdict.
